THIS CALL: PHASE 2, STRUCTURAL ASSETS (POINTS OF INFLUENCE AND OBSERVATION)

One more input: CONCEPTS, Phase 1's "Conceptual Assets" list. Each entry has a "Concept ID", "Concept Name", "Unit", "Information", "Objectives At Risk" (C, I, A), the ports it "Enters Through" and "Leaves Through", and its RTL "Entry Lines", "Held Lines" (where it is stored or produced) and "Exit Lines". Its "Rubric", "Rubric Reason" and "Attack" answer Phase 1's questions: use them as context, not as this call's answers, except as step 2 says.
Treat the list as fixed: analyse each entry, even a doubtful one, and add, merge or rename none. Say in "Notes" if one seems missing or wrong; do not analyse a missing one.

Steps, for each conceptual asset in CONCEPTS:

1. Walk. Work in the diagram of the conceptual asset's unit.
   Start at the blocks containing its held lines and at its entry and exit ports (for a port field, its port). A conceptual asset about a clock or reset itself starts at the blocks whose notes name it and at the instance blocks its arrows reach (2.2). Outside every generate statement, a held line that is a concurrent assignment to an output port belongs to no block: start at that assignment (see "Points" below); inside one, it belongs to its [generate] block: start there.
   An arrow from A to B moves the conceptual asset when one of its listed elements carries it (2.2) into B: on a "==>" arrow by an explicit flow, on either kind by an index. It decides the conceptual asset when its listed elements only decide whether, when or where B stores, moves, gates, clears or releases it. Judge each listed element only by what it does in B: read its counterparts whose cited lines are statements of B (B's members and the output ports or port fields B assigns; for an [inst] block, B's port-map lines), and those RTL lines. One element can carry different information on different lines (a bus data field carrying settings into one block, other data into another). Brackets can miss an element; counterparts and RTL show it. For an arrow from a block into an output port, bracketed or not, also judge the port's (for a record port, its fields') "gets value from" and "decided by" partners whose cited lines are statements of A, wherever those partners are assigned. An [inst] block's arrow into an output port is a port-map write when unbracketed or when its brackets name a port of the instantiated entity: for an instance of another IP the black-box rule decides; for one of this file, judge that port by its entry in the child entity's list.
   Forward: from an entry port or a holding block, follow the arrows that move the conceptual asset, and keep walking from each block they reach. An arrow whose elements carry the conceptual asset into a block that only tests them (a condition or a case selector) also reaches that block: list it as a point, but do not walk on from it.
   Backward: from an exit port or a holding block, follow backward the arrows that move it, and keep walking back from each block they come from. An arrow into a block on the walk makes its source block an influence point in two cases: its elements only decide the conceptual asset, or they are values from which the block computes the conceptual asset (an operand of an AND, an OR, a compare or a sum) without carrying it. List that block as a point, but do not walk back from it.
   Instances of another IP: when the conceptual asset enters one, every element the instance drives carries it (the black-box rule of section 1). Follow the arrows out of it that list those elements, and say in each point's "Answer Reason" that this is the assumption. Go one instance deep.
   Do not follow an arrow for a clock or reset it lists: it carries no value (2.2). Stop at the unit's ports, and where no arrow moves or decides the conceptual asset any further.
   Points: every block reached this way is a point, and so is every block whose own statements include one of the conceptual asset's held lines, even when no arrow you follow reaches it. A concurrent assignment to an output port that belongs to no block (shown by an arrow with brackets into an output port from a [process], [generate] or [logic] block, or from an [inst] block whose brackets name a signal of the unit rather than a port of the instantiated entity, or by an arrow from an input port straight into one) is a point too; name it after that output port, as OUTPUTS writes it. The unit's ports themselves are where the walk starts and ends; they are not points.

2. Questions. For every point, answer the four questions below for this conceptual asset:
   Confidentiality (the point as an observation point). Does the point expose the conceptual asset: can its value be read out, or inferred, there?
   Integrity (the point as an influence point). Does the point allow any modification of the conceptual asset?
   Availability. Can the point prevent the conceptual asset from being available for functional operation?
   Undermined expected behavior. Does the point have a special behavior, such as a privileged mode, an override, a bypass or test-packet injection, that can prevent the conceptual asset from being available for normal operation? A special behavior that changes the conceptual asset itself is answered under integrity.
   Assume the question's objective as section 3 says. A question whose objective Phase 1 did not list for this conceptual asset is answered "no": confidentiality needs C, integrity I, availability and undermined expected behavior A. If an entry lacks "Objectives At Risk", the list was left out, not emptied: rebuild it from its "Rubric", as Phase 1 does, and use it wherever this call names the objectives Phase 1 listed. A "yes" to confidentiality gives C, to integrity I, to availability A, and to undermined expected behavior the objective its "Rubric Reason" says the behavior breaks (I if it makes the output incorrect, A if it stops the function).
   A "yes" needs a mechanism the RTL shows or the black-box rule gives; cite its line. Judge by 2.9: its last bullet at a point that stores or sets the conceptual asset, the bullet before it elsewhere. If every answer is "no", say why.

3. Structural assets. At each point with any "yes", name the closed-set elements that store, carry, produce or control the conceptual asset there:
   - the block's members that do so. At a block that is a point only because an arrow out of it reaches the walk (an influence point), these are the members this arrow lists, plus any the counterparts show the brackets missed. A member acting on the conceptual asset only through another member is not named here;
   - the unit ports the block reads the conceptual asset from, and the output ports its arrows reach with the conceptual asset;
   - at a concurrent assignment to an output port: the output port or port field it writes, and the input ports or port fields it reads the conceptual asset from.
   Name the element carrying this conceptual asset: a record field when only that field carries it, even if the RTL also assigns or wires the whole record; the whole record or port only when every field it uses carries it. A unit port that only decides at this point (an enable, a strobe, an address) is not named here; step 5 checks it. When a state machine, apart from its reset, changes state only at steps a peer device's clock paces, and its next state depends only on its current state and one bit of a non-record input port (directly or through synchronizer stages), that port is the input port setting the state (2.6), although the RTL tests its bit only in conditions (an implicit flow, 2.2); the peer's clock line is never that port. Name that port here for the conceptual asset about that state, at the block reading it, although it only decides: walk back to it through those stages even past an influence point (step 1), even if CONCEPTS does not list it under "Enters Through".
   When the point reads or writes the same field of several unit ports of one role (differing only by an index), write one row for the lowest-numbered port and list the others in "Same Role" by exact closed-set name; never shorten that list.
   Each port in the conceptual asset's "Enters Through" and "Leaves Through" lists is a structural asset of it: name it at the point reading or writing it, even when every answer there is "no"; step 4 labels it by 2.6. Before returning the JSON, check that each such port has a row in "Assets" or "Not Reported", and so does each member the first bullet says to name at an influence point (as that bullet defines it) with a "yes"; a whole record's row covers its fields.
   Each element named here is a structural asset of this conceptual asset. If the conceptual asset passes port to port with no point between, say so in "Notes".

4. Primary. Label primary each structural asset of step 3 that 2.6 makes primary for this conceptual asset, including, for a decision or setting, the element holding or making it. Sequencing state (below) is no such decision or setting. A non-record unit port moving the conceptual asset's value one bit per step crosses the unit's boundary whole, as every bit passes it: the port's bit shifts into one end of a register carrying that value (2.2), or such a register's end bit drives the port, even through forwarding wires, synchronizer stages or one-bit registers, and even if the register holds other fields or the port carries other bits at other steps. Label it primary, not secondary as a path to the register, which keeps its own label. A serial clock line, carrying no bit of the value, is never such a port. An output port set only by decoding a stored selection, one line per value, returns it unmixed: label it primary for that selection. A non-record unit input port, other than a clock, reset, reset request, serial clock line or port whose bits only become ticks pacing a step, crosses the unit's boundary whole when the RTL copies it unchanged into the conceptual asset's value, alone or side by side with other such ports, or wires it straight into an instance input taking that value: label it primary, not secondary as a path to or decider of an element computed from it, which keeps its own label. Placing such ports side by side combines no per-region results (2.6); a signal doing only that and wired whole into an instance input is 2.6's inward signal, not a forwarding wire: label it primary too. A port step 3 names as setting a state machine's state is primary for the conceptual asset about that state; the state register keeps its own label and synchronizer stages stay barred. A wait or fault flag, a write-enable flag, or an access address that one instance outputs on a non-record port and hands to another instance or to this unit's logic is a hand-off; judge which it is from the port names at either end when the RTL cannot show it, and say so; a field of a record that an instance outputs is never a hand-off, even where it is wired on its own into another instance's non-record port. Label a hand-off primary for its conceptual asset where the instance outputs it: the output port of an instance of this file when this unit only wires that port into another instance, else the unit signal the port map drives; if another instance outputs the same address earlier or later, label each output. A hand-off that is one bit of a count is computed on the line assigning that bit to the output: the count is not primary for that conceptual asset but can be its secondary (2.7). Of this step's bars, only the port-buffer bar on a FIFO covers a hand-off. Each bar in this step (saying an element never qualifies or is not primary) holds even if CONCEPTS names the element, cites its lines as held lines or lists it under "Enters Through" or "Leaves Through", or where 2.6, 2.8 or another sentence would make it primary or 4.4 points at it; a bar worded "for any conceptual asset" also covers a conceptual asset about the element. A barred element can still be a secondary (2.7). What a rule judges as usual or does not cover is spared only from that rule's bar. A bus request or response record port, or any field of one, never qualifies (2.6), even as the conceptual asset's only entry or exit port. On a record port carrying accesses that name by address which of this unit's own registers, FIFOs, locks or memory words they read or write (not a cache's copies), the fields only saying whether an access happens, which way it goes and which register, FIFO or bytes it reaches (a strobe, a read or write bit, register-select address bits, byte enables), and a write enable whose assignment reads only these fields and whose only use is to let a register take the written data, are part of the information the access writes or reads, not information of their own. They never qualify for any conceptual asset, whether or not the port is a bus request or response record, and can be secondaries (2.7, direction b) of the element the access writes, reads or decides. Judged as usual: a separate signal decoded from these fields that gates or masks what a read returns or pops a FIFO of data the unit generates itself (the decision's own element), a register loaded with such a field's value, a memory address indexing words, a request held until served, a select routing it on, a strobe driven on to a unit output port, an operation's start pulse, and every non-record port. A one-bit register that one unconditional statement sets on every clock edge to a stored state bit or flag of this unit, copied or inverted and ANDed only with terms saying when it applies (a request strobe, its read or write bit, an operation-type decode), and that only a bus response's acknowledge or data fields read, only re-times that state to the response. It is never primary for any conceptual asset but can be a secondary (2.7). Judged as usual: that state where it is held; a register set only from the unit's input ports (a read enable from a strobe and a read or write bit); and a flag that a condition sets to a constant (a timeout error raised when a count reaches its limit). An internal array whose elements, one per port, this unit sets each to a whole bus request or response record (2.6) copied from one record or a constant, never qualifies for any conceptual asset: it only passes the transaction on, and a select or compare gating an element's strobe only decides that field (2.2) or mixes into it (2.6), so the decision stays where it is computed. A select computed from that compare (such as a bit-per-port vector) is the decision's own element and stays its primary. If the compare is inline in a condition, the decision has no element of its own and adds no primary, even when the held lines assign the array; do not move the primary to the record the array copies or its fields, which only feed the compare or carry the transaction. A single strobe, enable or request flag a decision gates is judged as usual. A record this unit only wires between a unit port and the port map of an instance of another IP, with no statement of this unit reading or writing it or its fields (a constant tied to it in a generate branch lacking the instance is no such statement), never qualifies for any conceptual asset, nor do its fields: the instance holds the value; the record only carries it. Judged as usual: a record this unit's statements read or write, a non-record port even if wired straight into an instance, and an element of this unit deciding whether or where the record passes. Relayed data is the data a transfer carries into or out of the unit (data loaded or stored, instruction words fetched, messages received or sent) when no statement of this unit stores it or computes from it: it only moves between a unit port and an instance of another IP, or between such instances, or into a statement that only mixes it with other values (an OR or a multiplexer). No element qualifies as primary for a conceptual asset about relayed data, alone or with only the acknowledge and ready lines timing its transfer, even in a unit executing instructions and where 4.2 points at it: Phase 1 does not keep such a concept, so it has no secondary (step 5); under other conceptual assets its elements keep their usual labels. Judged as usual: a transfer's address and direction; a wait or fault flag; an interrupt or debug request; a register read-back word, and the register contents an instance holds; an arithmetic, logic or compare result an instance computes; the value a mixing statement writes (such as the value written back to a register); and data the unit stores, shifts through its own register, generates or computes from, even when a buffer instance also holds it. Judge from port names which instance ports carry relayed data and which carry a computed result, and say so. A record that one instance of another IP drives whole and this unit wires whole into the port map of one or more other instances (decoded controls or fetch results moving between sub-units; closed set: the record's own entry gets its value from one instance port and gives it only to instance ports) holds nothing of this unit, even where a port map also takes one field alone, a statement of this unit reads one, or it carries the instructions this unit executes: that instance holds each value, and the record and its fields, one-bit flags included, only carry copies, none of them a non-record signal. Such a record and its fields never qualify for any conceptual asset, even where this step's clause on a decision or setting, or 2.6's outward clause or examples, would make one primary; where only these would qualify, the conceptual asset has none. They can be secondaries (2.7). Judged as usual: non-record signals handed between instances; non-record unit ports, even one wired straight into an instance (a debug or interrupt request line); records this unit's statements set, whole or field by field; records whose fields port maps or several instances set one by one; and, for its other values, an element this unit's statements compute from such a field and other values. In a unit that passes the bus requests arriving on an input bus request port out through an output bus request port, a register of one bit, or of one bit per requester, holds no information of its own when every assignment to it (directly or through its next-value signal), apart from clearing it and holding its value, copies or ORs in only the strobe, the lock bit or the response error bit of the access in progress, or sets it when a test reading only that access's own fields and build-time values holds (a route bit), and the unit reads it only to start, pass on, route, time or end that access, the access it serves or that locked sequence, or to drop the words that access fetched: the access already carries that value, and the register only re-times it. Such a register and a signal used only to compute its next value never qualify for any conceptual asset: one about such registers alone has no primary, and barring them makes no other element primary instead. They can be secondaries only in direction b (2.7). Judged as usual: a held request that a grant between requesters reads; the grant, its select and its strobe; an address decode picking which of several output bus request ports gets the access; a pending fence or flush that clears what the unit stores; a busy flag the unit sets when it issues an access itself; a timeout count, its suppression flag and its error; a reservation; a lock that software sets to guard later accesses; a read enable deciding whether stored data leaves on the response; and a cache's hit. A setting or decision whose only use, apart from a read-back, is to shape a serial link's clock line that the unit drives to or senses from a peer device (its polarity, its phase against the data, or holding it while the peer stretches it) never qualifies for any conceptual asset: Phase 1 does not keep it as one. Judged as usual: the link's data and select lines, its rate setting (how often the line toggles), an enable, and the unit's clock-enable outputs. A setting's only use is to shape a serial link's clock line also when, apart from its read-back, the only element its counterparts show it gives value to or decides is the one driving that line, and that element gives value to or decides nothing but the line, even where the line's phase sets when the peer samples or sends data. It then never qualifies for any conceptual asset, even a transfer-mode, format or rate concept; it can be a secondary (2.7). When a bus read returns, unchanged, words that some build (one generate branch) holds only in a ROM (no element, section 1), the element the ROM lookup writes in that build is where they are stored or computed in this unit (2.6), not a carrier, as no earlier element holds them: label it primary for their conceptual asset, even where another build only passes a stored word through it (each pair gets one label). A bus response field the lookup writes directly still never qualifies. In a cache (a unit answering a read from its own copy when a stored tag matches the address, else fetching over a backing bus), the copied words only copy the backing memory, and the tag and valid bits only record which words are copied, so the arrays holding them, and any signal or port only carrying their contents in or out, never qualify for any conceptual asset. Judged as usual: the cache's decisions (the hit, the bytes a write changes, the address, its fill, clear and invalidate commands, a pending fence or flush) and a memory that is itself the store. If none qualifies for a conceptual asset, give the reason in its "No Primary Reason". A register whose value, apart from constants and its own held value, only comes from part of an access's address field, directly or through its next-value wire or a wire only copying that part, and that only feeds other addresses or picks a memory word as an index, holds that address only while the access is served (2.6: a copy kept only while the value moves). It and its next-value wire never qualify as primary for any conceptual asset, even though the access sets them (2.6); they can be secondaries (2.7, direction a). Any other element that 2.6 says is not primary never qualifies either, even where this step's clause on a decision or setting would make it one. An internal signal (not a port) whose only assignment copies part of one element's bits (a slice), or joins signals that each do so from the same element, only carries that element's value (2.2), unless that element is a bus request or response record port or a field of one: such a slice is judged as usual (2.6). Otherwise it never qualifies as primary for any conceptual asset: the element it takes from keeps its own label, and the signal can be a secondary (2.7, direction a). A reset request that this unit only combines, gates, registers or passes on to a reset chain or reset output port never qualifies for any conceptual asset, nor do the input port bringing it in, its copies, that output port, or a chain only synchronizing or releasing a reset (a reset shift register): they only carry a decision judged where it is computed. Judged as usual: the record of a reset's cause, a compare outcome that restarts a counter, and, except as the next sentence says, a decision triggering a reset (such as a timeout), where it is computed, not a copy of it that the unit only gates or registers. A decision that a write was refused or carried a wrong value (a write while locked, a wrong password), its gated or registered copies, and a setting choosing only whether such a violation resets never qualify for any conceptual asset if their only uses, apart from a read-back, are to request a reset and record its cause. Judged as usual: the cause record, the lock refusing the write, a compare outcome that restarts a counter, a decision triggering a reset for another cause (such as a timeout) where it is computed, and a refused access raising a trap, a fault or a bus error. A tick, edge pulse or divider count made or picked inside the unit only to pace a step (apart from restarting itself, it only makes such a pulse or lets the step advance) is not primary for any conceptual asset unless an output port carries the pulse itself (2.2); a port the pulses only decide or time does not count. It can be a secondary only of a primary whose update it gates (2.7, direction b). Judged as usual: the element storing the rate setting, a request held until served, a start pulse decoded from a received command, a step counter (sequencing state, below, judges it), and a count whose compare with a limit raises a reset, an error or an interrupt, or sets an output level (a timeout or timer count). A register only recording that a count has started, read only to let that count advance or to qualify a compare on it, is not primary for any conceptual asset: it decides the count but never carries it (2.2). It can be a secondary only in direction b (2.7). Judged as usual: the compare's result, a flag a request or command sets until served (busy or pending), a start or clear pulse decoded from a command, a timeout's suppression flag, and a completion flag. An internal register (not a port) that copies bits of one other register of its own entity, directly and not as an index, whose other assignments write only constants, and that no condition reads, only holds that value while passing it on (2.6: a copy kept only while the value moves). It never qualifies as primary for any conceptual asset: the register it copies keeps its own label, and the copy can be a secondary (2.7, direction a). Partial results of a computation of this unit belong to its result and never qualify for any conceptual asset: a partial sum or product, an addend, a subtraction step or round value, a value before the final sign step, a value computed only to be copied, whole or in part, into the finished result's register, a compare only picking that result (a minimum or maximum), and a debiasing step's state and flag choosing which raw bits it accepts. Judged as usual: the element holding the finished result or that an output port takes it from, even while holding operand copies or partial values; a unit port; a signal handed whole to or from an instance; a count; a setting (such as signedness); a serial port's data shift register; and any other decision (such as a compare whose result picks or triggers what happens next, or checks combined per region or entry). A synchronizer stage is not primary for any conceptual asset: a register whose assignments, apart from constants, only copy in one unit input port's bit (directly or through a wire or type conversion only copying it) and shift its own earlier bits along; a wire only copying one of its bits is part of it. Judged as usual: the port itself; a register copying a port with none of its own earlier bits (an input register software reads back); a register whose new bit comes from a stage (a shift register assembling a received word); and an element mixing the port or a stage's bits with other values (a request held until served, a sticky flag). In a unit executing instructions, a word that an instance outputs for reads of its own control and status registers, and that this unit reads only in an OR into the word another instance takes in to answer such reads, only carries those registers to the other instance's read-back: the registers (a count, a protection setting, a configuration or status bit) stay inside the first instance, where no statement of this unit stores, computes or decides them (a constant tied to the word in a generate branch lacking that instance is no such statement). So these words (that word and the one the OR makes) never qualify for any conceptual asset, even one about those registers; where 2.6 would make only these primary, the conceptual asset has none; they can be secondaries (2.7). For a conceptual asset about the read-back, the other instance's output for such reads, which a statement of this unit merges directly into the value written back to a register, is the primary: the instance output this unit uses as the value itself (2.6, outward), although it carries the first instance's registers only by the black-box rule; 2.6's carrier sentences and this step's bar on what 2.6 says is not primary do not reach it. Judge from port names which instance outputs and inputs these are, and say so. Judged as usual: the value written back to a register, and the first instance's other outputs (a wait or fault flag, a result, an access address, a unit output port it drives), even when computed from those registers. If a FIFO instance's write data is a unit input port's value (a bus write, or bits shifted in from a serial input port), the FIFO only buffers data between two ports: its fill flags (holds data or has room), push and pop strobes, a command only clearing it, and a push-while-full flag (even a register of this unit) only time, gate, clear or report on that data and never qualify for any conceptual asset; barring them makes no other element primary instead. Judged as usual: the buffered data, an output port these flags decide (an interrupt request, a ready-to-receive line), a unit enable also clearing the FIFO, and the flags and controls of a FIFO holding data the unit generates (random bits). Any FIFO instance, whatever data it holds, only keeps each word while the word moves (2.6: a copy kept only while the value moves), so the signal wired to its write-data input and the signal its read-data output drives only carry the word, and the buffered data is judged where the unit generates it (random bits) or where it crosses the unit's boundary. These two signals never qualify as primary for any conceptual asset, even where 2.6's inward or outward clause, or this step's list sparing a signal handed whole to or from an instance, would make them primary; they can be secondaries (2.7, direction a). Judge from port names that an instance is a FIFO, which outputs are its flags and which ports carry its data, and say so. A constants-only wire this unit wires into an instance input, decided only by this unit's registers, one holding a command or setting a bus write stores (such as a wire asserted while a stored clear command is set or a stored enable is off), makes its own decision for that instance and holds no command or setting (2.2). It never qualifies as primary for a conceptual asset about such a command or setting; the register holding it keeps that primary, and the wire can be a secondary (2.7). A state machine's state register (not a flag that a request or command sets, held until that request is answered) or a bit, phase, word or step counter that restarts with each transfer or operation the unit carries out (even if one bit copies an enable or a queued command picks the first step), and is read only to pick that transfer's next step, to time or gate its strobes, commands, shifts, loads, acknowledges and multiplexers, or to point its address at the next word, is sequencing state: it only orders steps of information other elements hold, so neither it nor the busy flag decoded from it or the done flag it sets at its last step is information of its own. It and those flags never qualify for any conceptual asset, even one about that state or a transfer's control flow; where 2.6 would make only these primary, the conceptual asset has none. They can be secondaries only in direction b (2.7). Judged as usual: any unit port (an interrupt request these flags decide included), the enable and rate settings, the other elements these steps load or drive (a chip-select register, an address), the current grant (which requester holds a shared path), its select and its strobe, a reservation that one access sets and a later access checks, and a count whose compare with a limit raises a reset, an error or an interrupt, or sets an output level (a timeout or timer count), with that compare's flag and a timeout's suppression flag. Not covered, as their steps make the value or follow a peer's signals: a coprocessor, a unit shifting in bits it generates, and a test or debug access port that the peer's clock paces. In a coprocessor, a count that a multi-cycle operation steps on every clock cycle of its busy state, and whose end test only leaves that state, is a step counter, one piece of information with that state. Label the count primary for that state's conceptual asset, not secondary as a transition input. In a unit that shifts data bit by bit onto or off a serial data port, paced by the unit's own rate setting, the data shift register only holds each word while moving it between that port and the element that takes or gives the whole word, so the port is where that data crosses the unit's boundary whole (2.6). That shift register never qualifies as primary for any conceptual asset, even though the serial-port sentence above leaves it its own label and the sentences on partial results and synchronizer stages judge it as usual; it can be a secondary (2.7, direction a). A status bit that a bus read returns is not information of its own when every element it copies (even inverted) or combines is barred by this call's rule on a FIFO only buffering data between two ports or on sequencing state: it only tells software whether the buffered or shifted data can move or was lost, which that data, its settings and the output ports these elements decide already cover. The elements such a bit copies or combines stay barred under a conceptual asset about that status; where only they would be primary, it has none. They can be secondaries only as the rule barring them allows (2.7). A bit returning anything else, even in the same read word (a stored setting, selection or lock, the record of a reset's cause, a flag of a FIFO holding data the unit generates), is not covered. In a unit executing an instruction or atomic memory operation a processor issues to it (a coprocessor, an atomic read-modify-write), instruction or request fields only picking the operation or its result form (an opcode, a function code, an instruction-type bit), their stored copies, and flags decoded from them only naming the operation never qualify for any conceptual asset, being part of the operation they pick, not decisions of their own; they can be secondaries only in direction b (2.7). A flag whose assignment reads more than these fields (a start or valid signal, a state) does not only name the operation. Judged as usual: a start command or pulse, even one decoded per operation (a multiply start, a divide start), a register access's address and write enable, a completion flag, and a setting decoded from these fields (not a copy) changing how operands are read (such as signedness). Not covered: a plain bus read or write; the bar above on access command fields judges its read or write bit and a read enable made from it.
