THIS CALL: PHASE 2, STRUCTURAL ASSETS (POINTS OF INFLUENCE AND OBSERVATION)

One more input: CONCEPTS, Phase 1's "Conceptual Assets" list. Each entry has a "Concept ID", "Concept Name", "Unit", "Information", "Objectives At Risk" (C, I, A), the ports it "Enters Through" and "Leaves Through", and its RTL "Entry Lines", "Held Lines" (where it is stored or produced) and "Exit Lines". Its "Rubric", "Rubric Reason" and "Attack" answer Phase 1's questions: use them as context, not as this call's answers, except as step 2 says.
Treat the list as fixed: analyse each entry, even a doubtful one, and add, merge or rename none. Say in "Notes" if one seems missing or wrong; do not analyse a missing one.

Steps, for each conceptual asset in CONCEPTS:

1. Walk. Work in the diagram of the conceptual asset's unit.
   Start at the blocks containing its held lines and at its entry and exit ports (for a port field, its port). A conceptual asset about a clock or reset itself starts at the blocks whose notes name it and at the instance blocks its arrows reach (2.2). Outside every generate statement, a held line that is a concurrent assignment to an output port belongs to no block: start at that assignment (see "Points" below); inside one, it belongs to its [generate] block: start there.
   An arrow from A to B moves the conceptual asset when one of its listed elements carries it (2.2) into B: on a "==>" arrow by an explicit flow, on either kind by an index. It decides the conceptual asset when its listed elements only decide whether, when or where B stores, moves, gates, clears or releases it. Judge each listed element only by what it does in B: read its counterparts whose cited lines are statements of B (B's members and the output ports or port fields B assigns; for an [inst] block, B's port-map lines), and those RTL lines. One element can carry different information on different lines (a bus data field carrying settings into one block, other data into another). Brackets can miss an element; counterparts and RTL show it. For an arrow from a block into an output port, bracketed or not, also judge the port's (for a record port, its fields') "gets value from" and "decided by" partners whose cited lines are statements of A, wherever those partners are assigned. An [inst] block's arrow into an output port is a port-map write when unbracketed or when its brackets name a port of the instantiated entity: for an instance of another IP the black-box rule decides; for one of this file, judge that port by its entry in the child entity's list.
   Forward: from an entry port or a holding block, follow the arrows that move the conceptual asset, and keep walking from each block they reach. An arrow whose elements carry the conceptual asset into a block that only tests them (a condition or a case selector) also reaches that block: list it as a point, but do not walk on from it.
   Backward: from an exit port or a holding block, follow backward the arrows that move it, and keep walking back from each block they come from. An arrow into a block on the walk makes its source block an influence point in two cases: its elements only decide the conceptual asset, or they are values from which the block computes the conceptual asset (an operand of an AND, an OR, a compare or a sum) without carrying it. List that block as a point, but do not walk back from it.
   Instances of another IP: when the conceptual asset enters one, every element the instance drives carries it (the black-box rule of section 1). Follow the arrows out of it that list those elements, and say in each point's "Answer Reason" that this is the assumption. Go one instance deep.
   Do not follow an arrow for a clock or reset it lists: it carries no value (2.2). Stop at the unit's ports, and where no arrow moves or decides the conceptual asset any further.
   Points: every block reached this way is a point, and so is every block whose own statements include one of the conceptual asset's held lines, even when no arrow you follow reaches it. A concurrent assignment to an output port that belongs to no block (shown by an arrow with brackets into an output port from a [process], [generate] or [logic] block, or from an [inst] block whose brackets name a signal of the unit rather than a port of the instantiated entity, or by an arrow from an input port straight into one) is a point too; name it after that output port, as OUTPUTS writes it. The unit's ports themselves are where the walk starts and ends; they are not points.

2. Questions. For every point, answer the four questions below for this conceptual asset:
   Confidentiality (the point as an observation point). Does the point expose the conceptual asset: can its value be read out, or inferred, there?
   Integrity (the point as an influence point). Does the point allow any modification of the conceptual asset?
   Availability. Can the point prevent the conceptual asset from being available for functional operation?
   Undermined expected behavior. Does the point have a special behavior, such as a privileged mode, an override, a bypass or test-packet injection, that can prevent the conceptual asset from being available for normal operation? A special behavior that changes the conceptual asset itself is answered under integrity.
   Assume the question's objective as section 3 says. A question whose objective Phase 1 did not list for this conceptual asset is answered "no": confidentiality needs C, integrity I, availability and undermined expected behavior A. If an entry lacks "Objectives At Risk", the list was left out, not emptied: rebuild it from its "Rubric", as Phase 1 does, and use it wherever this call names the objectives Phase 1 listed. A "yes" to confidentiality gives C, to integrity I, to availability A, and to undermined expected behavior the objective its "Rubric Reason" says the behavior breaks (I if it makes the output incorrect, A if it stops the function).
   A "yes" needs a mechanism the RTL shows or the black-box rule gives; cite its line. Judge by 2.9: its last bullet at a point that stores or sets the conceptual asset, the bullet before it elsewhere. If every answer is "no", say why.

3. Structural assets. At each point with any "yes", name the closed-set elements that store, carry, produce or control the conceptual asset there:
   - the block's members that do so. At a block that is a point only because an arrow out of it reaches the walk (an influence point), these are the members this arrow lists, plus any the counterparts show the brackets missed. A member acting on the conceptual asset only through another member is not named here;
   - the unit ports the block reads the conceptual asset from, and the output ports its arrows reach with the conceptual asset;
   - at a concurrent assignment to an output port: the output port or port field it writes, and the input ports or port fields it reads the conceptual asset from.
   Name the element carrying this conceptual asset: a record field when only that field carries it, even if the RTL also assigns or wires the whole record; the whole record or port only when every field it uses carries it. A unit port that only decides at this point (an enable, a strobe, an address) is not named here; step 5 checks it. When a state machine, apart from reset, changes state only at steps a peer device's clock paces, and its next state depends only on its current state and one bit of a non-record input port (directly or through synchronizer stages), that port, never the peer's clock line, is the input port setting the state (2.6), though only conditions test its bit (an implicit flow, 2.2). Name that port here for the conceptual asset about that state, at the block reading it, although it only decides: walk back to it through those stages even past an influence point (step 1), even if CONCEPTS does not list it under "Enters Through".
   When the point reads or writes the same field of several unit ports of one role (differing only by an index), write one row for the lowest-numbered port and list the others in "Same Role" by exact closed-set name; never shorten that list.
   Each port in the conceptual asset's "Enters Through" and "Leaves Through" lists is a structural asset of it: name it at the point reading or writing it, even when every answer there is "no"; step 4 labels it by 2.6. Before returning the JSON, check that each such port has a row in "Assets" or "Not Reported", and so does each member the first bullet says to name at an influence point (as that bullet defines it) with a "yes"; a whole record's row covers its fields.
   Each element named here is a structural asset of this conceptual asset. If the conceptual asset passes port to port with no point between, say so in "Notes".

4. Primary. Among the structural assets of step 3, label primary each element that 2.6 makes primary for this conceptual asset: where its value is stored or computed in this unit, where it crosses the unit's boundary whole, or, for a decision or setting, the element that holds or makes it. Outside a coprocessor, sequencing state (below) is not such a decision or setting. A non-record unit port (not a serial clock line) that moves the conceptual asset's value one bit per step crosses the boundary whole, as every bit passes it: the RTL shifts the port's bit into one end of a register carrying that value (2.2), or drives the port from such a register's end bit, even through forwarding wires, synchronizer stages or one-bit registers, and even if the register holds other fields or the port carries other bits at other steps. Label the port primary, not secondary as a path to the register, which keeps its own label.  An output port set only from a stored selection, one line per value (a decode), returns it unmixed: label it primary for that selection. A non-record output port (not a serial clock line), of the unit or of an entity of this file the unit instantiates, whose only assignment is one concurrent statement copying unchanged a whole element (no index or slice) that this walk labels primary, returns that element unmixed (2.6), also for a setting, and even where the unit wires the port into a FIFO's write-data input, as the FIFO sentence below bars the unit's signal on that input, not the port driving it, and except an instance's port whose port-map signal in this unit gets its value from that port and lists "decides" partners (that signal is primary instead, by the sentence on a value an instance of this file outputs, or, for a hand-off, by the sentences on hand-offs): label the port primary, not secondary as a path to that element, which keeps its own label. A non-record unit input port (not a clock, a reset, a reset request, a serial clock line, or a port whose bits only become ticks pacing a step) that the RTL copies unchanged into the conceptual asset's value, alone or side by side with other such ports, or reduces to one bit that alone, apart from constants, sets the register holding the conceptual asset (the input port setting it, 2.6), or wires straight into an instance input taking that value, crosses the boundary whole: label it primary for that conceptual asset, not secondary as a path to or a decider of an element computed from it, which keeps its own label; this sentence only adds primaries, so a port it does not cover (such as one the RTL only tests, or reduces to one bit it then mixes with other values) is labelled as if this sentence were absent. Placing such ports side by side combines no per-region results (2.6), and a signal doing only that and wired whole into an instance input is the inward signal of 2.6, not a forwarding wire: label it primary too. Label a port that step 3 names as setting a state machine's state primary for the conceptual asset about that state; the state register keeps its own label, and the synchronizer stages defined below stay barred.
Reading a rule below: check its scope, then each criterion, then each exception it lists, in that order, against the RTL; where a criterion says "only", "every" or "one element", check every assignment or use, not one. Its outcome follows only for an element in scope that meets every criterion (one, where marked "any of") and that no listed exception covers.
- Scope: a wait, fault or write-enable flag, or an access address.
  Criteria: that one instance outputs on a non-record port to another instance or this unit's logic.
  Exceptions: a field of a record an instance outputs on a record port is never a hand-off, even wired alone into another instance's non-record port; apart from the port-buffer bar on a FIFO, no bar in this step covers a hand-off.
  Outcome: a hand-off: label a hand-off primary for its conceptual asset where the instance outputs it: the output port of an instance of this file when this unit only wires that port into another instance, and otherwise the unit signal the port map drives; when another instance outputs the same address earlier or later, label each output. When a hand-off is one bit of a count, the line assigning that bit to the output is where it is computed: the count is not primary for that conceptual asset, and can be its secondary (2.7).
  Evidence: if the RTL cannot show which kind it is, judge from the port names at either end and say so.
A value that an instance of this file outputs on a non-record port, other than a hand-off, crosses into this unit whole at the unit signal that port drives through the port map when that signal's closed-set entry gets its value from that instance port and lists "decides" partners, because this unit's decisions then use the value only through that signal (2.6, outward: the instance output this unit then uses as the value itself); when that signal lists no "decides" partner, this sentence does not apply. Label that signal primary for its conceptual asset; the instance output port is not primary for it and can be its secondary (2.7, direction a). Where an accepted compare outcome, an access address or an operand setting is held: the outcome of a compare of a written value with a fixed value is held at the register that the branch taken when the value matches sets, as that register is where the compare is computed (step 3) even when it keeps the outcome for one cycle only and only restarts a counter, so it is neither the action the compare triggers nor a one-cycle request folded into what it times, and the line where the other branch requests a reset is never its held line; an access address that leaves the unit in the address field of a bus request record port, which never holds it (2.6), is also held at each non-record port on which an instance of another IP outputs that address to another instance, judged from the port names at either end (an address output, or an output wired into an address input) as a hand-off; and a setting decoded from instruction fields that changes how operands are read (signedness), not a flag only naming the operation, is held at the lines assigning it, even inside a concept about the operation it belongs to; Phase 1 cites each such line as a held line of the concept whose information it is, and Phase 2, at the block owning each such line, names the element the line assigns, even when no arrow it follows lists that element, and labels it primary for that concept. Each bar in this step (saying an element never qualifies or is not primary) holds even if CONCEPTS names the element, cites its lines as held lines or lists it under "Enters Through" or "Leaves Through", or where 2.6, 2.8 or another sentence would make it primary or 4.4 points at it; a bar worded "for any conceptual asset" also covers a conceptual asset about the element. A barred element can still be a secondary (2.7). What a rule judges as usual or does not cover is spared only from that rule's bar. A bus request or response record port, or any field of one, never qualifies (2.6), even as the conceptual asset's only entry or exit port.
- Scope: Accesses on a record port (never on non-record ports, even ones together carrying an access) addressing this unit's own registers, FIFOs, locks or memory words (not a cache's copies).
  Criteria (any of): (1) the fields only saying whether an access happens, its direction and which register, FIFO or bytes it reaches (a strobe, a read or write bit, register-select address bits, byte enables; an address indexing a memory's stored words is the access address, not one of them); (2) a write enable whose assignment reads only these fields and that only lets a register or FIFO take the written data.
  Exceptions: Judged as usual: a separate signal decoded from these fields that gates or masks what a read returns or pops a FIFO of data the unit generates itself (the decision's own element), a register loaded with such a field's value, a request held until served, a select routing it on, a strobe driven on to a unit output port other than as an acknowledge, and an operation's start pulse (not an access's strobe or write enable).
  Outcome: they are part of the information the access writes or reads, not information of their own. They never qualify for any conceptual asset, whether or not the port is a bus request or response record, and can be secondaries (2.7, direction b) of the element the access writes, reads or decides.
- Bus handshake copies (b).
  Scope: In a unit passing bus requests from an input bus request port to an output one, a register of one bit, or one bit per requester, not a request waiting for a grant (a rule below).
  Criteria: (1) every assignment to it (directly or through its next-value signal), apart from clearing or holding it, copies or ORs in only the strobe, lock bit or response error bit of the access in progress, or sets it when a test reading only that access's fields and build-time values holds (a route bit); (2) the unit reads it only to start, pass on, route, time or end that access, the access it serves or that locked sequence, or to drop words that access fetched.
  Exceptions: the grant, its select and strobe; an address decode choosing which of several output bus request ports gets the access; a pending fence or flush clearing what the unit stores; a busy flag set when the unit itself issues an access; a timeout count, its error and its suppression flag; a reservation; a software-set lock guarding later accesses (not a copied lock bit); a read enable deciding whether stored data leaves on the response; and a cache's hit, each with its next-value signal.
  Outcome: holds no information of its own: the register only re-times a value the access already carries. Such a register and a signal used only to compute its next value never qualify for any conceptual asset: one about such registers alone has no primary, and barring them makes no other element primary instead. They can be secondaries only in direction b (2.7).
- Bus handshake copies (c).
  Scope: A one-bit register.
  Criteria: (1) that one unconditional statement sets on every clock edge to a stored state bit or flag of this unit, copied or inverted and ANDed only with terms saying when it applies (a request strobe, its read or write bit, an operation-type decode); (2) that only a bus response's acknowledge or data fields read.
  Exceptions: that state, where held; a register set only from the unit's input ports (a read enable from a strobe and a read or write bit); and a flag that a condition sets to a constant (a timeout error raised at a count's limit).
  Outcome: only re-times that state to the response. It is never primary for any conceptual asset but can be a secondary (2.7).
- Forwarded transactions (a).
  Scope: An internal array.
  Criteria: (1) whose elements, one per port, this unit sets each to a whole bus request or response record (2.6); (2) copied from one record or a constant.
  Exceptions: A single strobe, enable or request flag a decision gates.
  Outcome: never qualifies for any conceptual asset: it only passes the transaction on, and a select or compare gating an element's strobe only decides that field (2.2) or mixes into it (2.6), so the decision stays where it is computed. A select computed from that compare (such as a bit-per-port vector) is the decision's own element and stays its primary. If the compare is inline in a condition, the decision has no element of its own and adds no primary, even when the held lines assign the array; do not move the primary to the record the array copies or its fields, which only feed the compare or carry the transaction.
- Forwarded transactions (b).
  Scope: A record.
  Criteria: (1) this unit only wires between a unit port and the port map of an instance of another IP; (2) with no statement of this unit reading or writing it or its fields (a constant tied to it in a generate branch lacking the instance is no such statement).
  Exceptions: a record this unit's statements read or write, a non-record port even if wired straight into an instance, and an element of this unit deciding whether or where the record passes.
  Outcome: never qualifies for any conceptual asset, nor do its fields: the instance holds the value; the record only carries it.
- Forwarded transactions (c).
  Scope: Relayed data is data a transfer carries into or out of the unit (data loaded or stored, instruction words fetched, messages received or sent).
  Criteria: (1) no statement of this unit stores it or computes from it; (2) it only moves between unit ports, between a unit port and an instance of another IP, between such instances, through a register stage, or into a statement only mixing it with other values (an OR, a multiplexer).
  Exceptions: a port of a bus whose address this unit drives on a non-record output port of its own and whose acknowledge it takes on a non-record input port of its own: judge each such port as usual (2.6, 2.7), but under a conceptual asset about what crosses that bus the relayed-data bar still keeps every other element from being primary (each can be a secondary of those ports, 2.7); a transfer's address and direction; a wait or fault flag; an interrupt or debug request; a register read-back word, and the register contents an instance other than a buffer or register stage holds; an arithmetic, logic or compare result an instance computes; the value a mixing statement writes (such as the value written back to a register), unless that statement mixes only relayed data, bus responses and constants; and data the unit stores (not a register stage's copy), shifts through its own register, generates or computes from, even when a buffer instance also holds it.
  Outcome: No element qualifies as primary for a conceptual asset about relayed data, alone or with only the acknowledge and ready lines timing its transfer, even in a unit executing instructions and where 4.2 points at it: Phase 1 does not keep such a concept, so it has no secondary (step 5); under other conceptual assets its elements keep their usual labels.
  Evidence: Judge from port names which instance ports carry relayed data and which a computed result, and say so; judge from port names which ports are that bus's address, acknowledge and other lines, and say so.
A record driven whole by one instance of another IP and wired whole into one or more other instances' port maps (decoded controls or fetch results between sub-units; closed set: the record's own entry gets its value from one instance port and gives it only to instance ports) holds nothing of this unit, even if a port map also takes a field alone, a statement of this unit reads one, or it carries the instructions this unit executes: that instance holds each value; the record and its fields, one-bit flags included, only carry copies, and none is a non-record signal. Such a record and its fields never qualify for any conceptual asset, even where this step's clause on a decision or setting, or 2.6's outward clause or examples, would make one primary; where only these would qualify, the conceptual asset has none. They can be secondaries (2.7). Judged as usual: non-record signals handed between instances; non-record unit ports, even one wired straight into an instance (a debug or interrupt request line); records this unit's statements set, whole or per field; records whose fields port maps or several instances set separately; and, for its other values, an element this unit's statements compute from such a field and other values.
- Clocks and resets (a).
  Scope: any unit.
  Criteria: (1) any of: a clock or reset input (tagged so, or only wired into instances); a reset request (one reaching a reset chain or reset output port; a FIFO or buffer clear is not one) that this unit only combines, gates, registers or passes on to such a chain or port (every element it gives value to or decides), the input port bringing it in (never a bus data port or field), its copies (its value unchanged) or any reset output port; a chain only synchronizing or releasing a reset, giving value only to its next stage or a reset output port (a reset shift register, a registered reset copy); (2) not the record of a reset's cause, a compare outcome that restarts a counter, or, unless (c) bars it, a decision triggering a reset (a timeout) where it is computed (not a copy).
  Outcome: never qualify for any conceptual asset.
- Clocks and resets (b).
  Scope: any unit.
  Criteria: (1) a serial link's clock line (the unit port itself, to or from a peer device) or a setting or decision whose only use, apart from a read-back, is to drive or shape that line (polarity, phase against the data, holding it while the peer stretches it), including when, apart from its read-back, its counterparts show it gives value to or decides only the element driving that line, which gives value to or decides nothing but the line, even where the line's phase sets when the peer samples or sends data; (2) not the link's data or select line, its rate setting (how often the line toggles) or the unit's clock-enable output.
  Outcome: never qualifies for any conceptual asset, even a transfer-mode, format or rate concept: Phase 1 does not keep it as one; it can be a secondary (2.7).
- Clocks and resets (c).
  Scope: a decision that a write was refused or carried a wrong value (a write while locked, a wrong password), its gated or registered copies, or a setting choosing only whether such a violation resets.
  Criteria: (1) apart from a read-back, it gives value to or decides at least one element, and every one is a reset request (as in (a)) or the record of that reset's cause; (2) not the cause record, the lock refusing the write, or a compare outcome that restarts a counter.
  Outcome: never qualify for any conceptual asset.
When a bus read returns, unchanged, words that some build (one generate branch) holds only in a ROM (no element, section 1), the element the ROM lookup writes in that build is where they are stored or computed in this unit (2.6), not a carrier, as no earlier element holds them: label it primary for their conceptual asset, even where another build only passes a stored word through it (each pair gets one label). A bus response field the lookup writes directly still never qualifies. In a cache (a unit answering a read from its own copy when a stored tag matches the address, else fetching over a backing bus), the copied words only copy the backing memory, and the tag and valid bits only record which words are copied, so the arrays holding them, and any signal or port only carrying their contents in or out, never qualify for any conceptual asset. Judged as usual: the cache's decisions (the hit, the bytes a write changes, the address, its fill, clear and invalidate commands, a pending fence or flush) and a memory that is itself the store. If none qualifies for a conceptual asset, give the reason in its "No Primary Reason". A register whose value, apart from constants and itself, comes only from part of an access's address field, directly or through its next-value wire (a wire giving value to or deciding nothing but that register) or a wire only copying that part, and that only feeds other addresses or indexes a memory, holds that address only while the access is served (2.6: a copy kept only while the value moves). It and its next-value wire (not a wire only copying that part and also giving value to or deciding another element: that wire is the address's own element, judged as usual) never qualify as primary for any conceptual asset, even though the access sets them (2.6); they can be secondaries (2.7, direction a). Any other element that 2.6 says is not primary never qualifies either, even where this step's clause on a decision or setting would make it one.
- Slices.
  Scope: a signal (not a port).
  Criteria: (1) its assignments (each line), leaving out only its reset assignment and constants in another generate branch, each take only slices or indexed bits (never the whole element) of one element, the same in every line (one closed-set entry: for a record, one field), alone or concatenated (side by side, with no constant, not combined by a logic or arithmetic operator), even through signals; (2) the element the bits come from is not a bus request or response record port, a field of one, or a write's data.
  Outcome: it only carries that element's value (2.2) and never qualifies as primary for any conceptual asset: the element it takes from keeps its own label, and the signal can be a secondary (2.7, direction a).
- Pacing pulses.
  Scope: A tick, edge pulse or divider count made or picked inside the unit.
  Criteria: (1) only to pace a step (apart from restarting itself, it only makes such a pulse or lets the step advance).
  Exceptions: if it is a pulse an output port carries (2.2) (not a port the pulses only decide or time); the element storing the rate setting; an enable deciding whether the count runs at all; a request held until served; a start pulse, or its copy, decoded from a received command or access; a count whose compare with a limit raises a reset, error or interrupt, or sets an output level; a step counter (sequencing state, below, judges it).
  Outcome: not primary for any conceptual asset. It can be a secondary only of a primary whose update it gates (2.7, direction b).
A register only recording that a count has started, read only to let that count advance or to qualify a compare on it, is not primary for any conceptual asset: it decides the count but never carries it (2.2). It can be a secondary only in direction b (2.7). Judged as usual: the compare's result, a flag a request or command sets until served (busy or pending), a start or clear pulse decoded from a command, a timeout's suppression flag, and a completion flag.
- Second copies.
  Scope: an internal register (not a port).
  Criteria: (1) that directly copies bits, not as an index; (2) of one other register of its own entity; (3) whose other assignments write only constants; (4) that no condition reads.
  Outcome: it is a copy kept only while the value moves (2.6) and never qualifies as primary for any conceptual asset: the register it copies keeps its own label, and the copy can be a secondary (2.7, direction a).
- Working values (a).
  Scope: a computation of this unit.
  Criteria (any of): (1) a partial sum or product, an addend, a subtraction step or round value; (2) a value before the final sign step; (3) a value computed only to be copied, whole or in part, into the finished result's register; (4) a compare only picking that result (a minimum or maximum); (5) a debiasing step with its state and flag.
  Exceptions: judged as usual: the element holding the finished result or that an output port takes it from, even while holding operand copies or partial values; a unit port; a signal taking an instance output whole or handing the finished result whole to an instance; a count; a setting that changes how operands are read (signedness); a serial port's data shift register and a one-bit register feeding it; and any other decision (such as a compare whose result picks or triggers what happens next, or checks combined per region or entry).
  Outcome: partial results belong to the computation's result and never qualify for any conceptual asset.
- Working values (b).
  Scope: a synchronizer stage; a wire only copying one of its bits is part of it.
  Criteria: a register whose assignments, apart from constants, only (1) copy in one unit input port's bit (directly or through a wire or type conversion only copying it) and (2) shift its own earlier bits along.
  Exceptions: judged as usual: the port itself; a register copying a port with none of its own earlier bits (an input register software reads back); a shift register assembling a received word from a stage's bits; and an element mixing the port or a stage's bits with other values (a request held until served, a sticky flag).
  Outcome: it is not primary for any conceptual asset.
In a unit executing instructions, a word that an instance outputs for reads of its own control and status registers, and that this unit reads only in an OR into the word another instance takes in to answer such reads, only carries those registers to the other instance's read-back: the registers (a count, a protection setting, a configuration or status bit) stay inside the first instance, and no statement of this unit stores, computes or decides them (a constant tied to the word in a generate branch lacking that instance is no such statement). So these words (that word and the one the OR makes) never qualify for any conceptual asset, even one about those registers; where 2.6 would make only these primary, the conceptual asset has none; they can be secondaries (2.7). For a conceptual asset about the read-back, the other instance's output for such reads, which a statement of this unit merges directly into the value written back to a register, is the primary: the instance output this unit uses as the value itself (2.6, outward), although it carries the first instance's registers only by the black-box rule; 2.6's carrier sentences and this step's bar on what 2.6 says is not primary do not reach it. Judge from port names which instance outputs and inputs these are, and say so. Judged as usual: the value written back to a register, and the first instance's other outputs (a wait or fault flag, a result, an access address, a unit output port it drives), even when computed from those registers.
